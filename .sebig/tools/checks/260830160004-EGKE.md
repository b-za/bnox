  - "Index freshness check"
tags:
  - "check"
  - "verification"
  - "meta-procedure"
implements: ["260825144541-DFTS"]
procedure: |
  1. Run `id-register --format json` to get all current note IDs
  2. For each index file (type: "index" in docs/graph/):
     a. Extract all wiki-linked IDs from index body
     b. Compare with current id register
     c. Report: IDs in index but not in register (stale), IDs in register but not in index (missing)
  3. For each index entry: search forward for newer decisions that might change it
     a. Get index entry ID and title
     b. Search decisions (type: "decision") with timestamp > index's `last_generated`
     c. Check if decision's `connections:` or body links reference the entry ID
     d. If yes: index entry potentially stale → flag for rebuild

what_to_look_for:
  - Index entries for deleted/superseded notes
  - New notes not in any index
  - Decisions after `last_generated` that affect indexed items
  - Index `last_generated` timestamp older than newest decision

pass_fail_criteria: |
  PASS: Zero stale entries, zero missing entries, no post-index decisions affecting entries unflagged.
  FAIL: Any stale/missing entry, or affecting decision not flagged.
  Output: (index_file, stale_ids[], missing_ids[], affecting_decisions[])
