implements: ["260825144541-DFTS"]
procedure: |
  For each decision note created/updated this session:

  1. Identify decision domain (meta-procedure vs subject-matter)
     - meta-procedure → destination in `tools/` (script, check, guide)
     - subject-matter → destination in `docs/graph/` (spec, concept, contract)

  2. Extract decision's `connections:` targets (MODIFIES, IMPLEMENTS, REFERENCES edges)
     - If no `connections:`, scan body for wiki links to specs/concepts/contracts

  3. For each target:
     a. Verify target file exists
     b. Verify target file has been updated (timestamp, content) to reflect decision
     c. For meta-procedure: check `tools/scripts/`, `tools/checks/`, `tools/meta/`
     d. For subject-matter: check `docs/graph/` relevant spec/concept/contract

  4. Report: decision_id, domain, target_file, updated (yes/no), evidence

what_to_look_for:
  - Decision with no `connections:` and no body links to specs
  - Target file exists but unchanged (decision not propagated)
  - Meta-procedure decision targeting subject-matter file (or vice versa)
  - Target file has "What This Does Not Do" but doesn't mention decision

pass_fail_criteria: |
  PASS: Every decision has at least one target file updated with decision impact.
  FAIL: Decision has no traceable destination update.
  Output: List of (decision_id, domain, target_file, updated, evidence)
