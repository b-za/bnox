# Hows System

## What Are Hows

**Hows** are all meta-level rules, conventions, protocols, policies, standards, safeguards, and templates that govern *how we work* in this repository.

> "Our hows are documented in `tools/meta/`"

Each how is a file in `tools/meta/` with:
- Current state (the "how")
- Links to decision notes that evolved it
- Category tag: `how: convention|working-rule|protocol|policy|standard|safeguard|template`
- `how:` tag for querying

## How Hows Work

### Each How Has a File

`tools/meta/2608XXYYYYYY-XXXX.md` with:

```yaml
how: "convention|working-rule|protocol|policy|standard|safeguard|template"
tags: ["how", "convention|working-rule|...", "domain"]
```

### Hows Reference Each Other

- **Link, don't copy** — `[How Name]([[id]])`
- **Decision traceability** — Link to decision notes that evolved it
- **No duplication** — Single source of truth

### Hows Evolve

1. Create decision note for change
2. Update how file with new state
3. Link to decision note
3. Regenerate `agents.md` fence if referenced there

## How to Create a New How

1. **Create decision note** for the change
2. **Create how file** in `tools/meta/` with:
   - `how:` category tag
   - Current state
   - Links to decision notes
   - `how:` tag for querying
3. **Run** `tools/scripts/hows-index --write` to regenerate index
4. **Reference** via `[[id]]` links, not copies

## Querying Hows

```bash
# All hows
grep -r '^how:' tools/meta/

# By category
grep -r 'how: convention' tools/meta/
grep -r 'how: safeguard' tools/meta/

# All safeguards
grep -r 'how: safeguard' tools/meta/
```

## What This Does Not Do

- Does not enforce hows automatically (except safeguards)
- Does not replace reading the actual how files
- Does not define enforcement for non-safeguard hows
- Does not create individual how files (separate task)
