# bnox-bg lessons, fix batch (series 0.3, patch 0/3/1)

Converted from the archived decision log ([[docs/graph/261111230000-D005|converted archive decisions]]): `docs/archive/design/process/05-decisions.md` line 521, D-017 (accepted).

## Context

agenthub (bnox-bg) is the first real consumer of bnox 0/3/0. Its gotcha log (bnox-bg `docs/graph/*-G0xx.md`) and host config show bnox bugs worked around host-side: G20 (pure flake eval cannot read `/srv/<thing>/.bnox/`, so the documented `source = "/srv/<thing>"` can never load a manifest under `nixos-rebuild --flake`), G21/G22/G24/G25/G31 (the generated `<thing>-build` unit is too locked down to build: libgit2 safe.directory, unwritable fetcher cache, podman runtime paths, nix build-log dir, `podman save` refusing to overwrite a same-sha tar), G28 (host-install units get slot path units but no env files), missing slot files (podman refuses to start a container whose env file is absent; bnox-bg pre-creates them via tmpfiles). Reviewed one at a time with bh. Also: 0/3/0 was frozen after a single probe container round-trip — the deploy pipeline was never run against a real thing on the locked broker, and was broken (G23).

## Decision

1. **Thing manifest and thing code have separate sources.** `bnox.things.<name>.source` is where bnox reads `.bnox/` at evaluation — documented as a locked flake input of the host repo (a store path). The code is always built from the git checkout `/srv/<name>` by the deploy pipeline (already hardcoded in `pipeline.nix`). This keeps [[docs/graph/261111230006-R006|Thing hosting architecture]]'s hard constraint (app deploys never trigger `nixos-rebuild`); the lock only needs bumping when `.bnox/` itself changes. Option A (flake input for both, deploy = lock bump + rebuild) was considered and rejected precisely because it violates [[docs/graph/261111230006-R006|Thing hosting architecture]]. The build unit **warns** when `/srv/<name>/.bnox/` differs from the evaluated manifest.
2. **Build unit fixes, taken over from bnox-bg as proven:** system `/etc/gitconfig` `safe.directory` for every thing checkout (covers nix's libgit2, not just the git CLI); `XDG_CACHE_HOME=/var/lib/<name>/.cache`; ReadWritePaths gain `/run/lock /run/libpod /run/containers /var/cache/containers /nix/var/log/nix`; the same-sha tar is removed before `podman save` (bnox-bg wiped the whole images dir, which would also destroy the rollback tarballs [[docs/graph/261111230011-R011|App-layer deployment mechanism]] keeps — narrowed to the one file).
3. **Host-install runtime loads slots as env files** (`EnvironmentFile`), like the container runtime: `nats_seed` required, other slots `-`-prefixed. The host-install unit's secrets dir becomes read-only (it was writable — an app must not be able to overwrite its own credentials). Option B (files only, app reads by path) rejected for consistency; env inheritance by child processes changes little since the app user could read the files anyway.
4. **bnox creates every declared slot as an empty file, root:root 0600** (tmpfiles `f`, which never rewrites an existing file — G45). Supersedes the "slot owned by the thing's user" wording in the series docs: systemd reads env files as PID 1, so root-only is strictly safer.
5. **Pipeline publishes under NATS auth (G23) and the nats-py dispatcher's missing nkey support (G4) are NOT patched here** — they are solved by [[docs/graph/261111230018-R018|NATS identity: logins always, two-level permissions, roles (series 0.4)]] (NATS identity), not by another stopgap.
6. **Done rule (process):** a version may only be set `status: done` after, on a real host, (a) a real thing has completed the full deploy path git push → webhook → sync → build → restart, and (b) `bnox-validate` passes (once it exists, [[docs/graph/261111230020-R020|Host-install switches, image helper, self-test (series 0.4)]]; until then, the NATS round-trip checks the host already has).

## Consequences Elsewhere

- bnox-bg can drop its G21/G22/G24/G25/G31 build-unit overrides, its slot-file tmpfiles and its hermes `EnvironmentFile` lines once it pins 0/3/1.
- Hosts using `source = "/srv/<thing>"` were already broken under flake eval; docs now show the flake-input form.
- Slot file ownership changes from thing user to root on upgrade only for newly-created files; existing files keep their mode (tmpfiles `f` does not touch them).
