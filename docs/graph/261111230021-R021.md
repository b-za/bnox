# Host-wide egress lockdown is opt-in (series 0.4)

Converted from the archived decision log ([[docs/graph/261111230000-D005|converted archive decisions]]): `docs/archive/design/process/05-decisions.md` line 595, D-021 (accepted).

## Context

[[docs/graph/261111230019-R019|Thing config and network exposure: `env`, egress, inbound (series 0.4)]]'s egress rules bind bnox-generated units only (per-unit IPAddressAllow + per-thing proxies). bnox-bg's agenthub additionally runs owner-based nftables output rules (`egress.nix`) that stop everything else — stray processes, interactive users, hand-written units — from reaching ports 80/443.

## Decision

bnox ships it as an opt-in switch, `bnox.egress.hostLockdown` (default off), plus `hostLockdownAllowUsers`. Allowed out on 80/443: root, the egress proxies (now a static `bnox-egress` user so they can be matched), Caddy, host-install things granted direct `"any"`, and the listed users. Fail-open (policy accept + explicit drops), output hook only. Rules are rendered at unit start with numeric uids. Containers are not matched (bridge traffic is forwarded; slirp4netns runs as root) — their per-unit rules scope them.

## Alternatives Considered

default-on (matches "locked by default", but breaks ordinary use of a desktop host like the MacBook); leave it to host repos (agent hosts would each re-implement it).
