2026-07-27 — **D-007 ACCEPTED — Secrets architecture: Hybrid-1 default + Hybrid-2-ready abstraction.** User requirement: changing a thing's secrets must NOT trigger host rebuild — rules out pure push-at-deploy. Chicken-and-egg forces infra secrets to be push-at-deploy no matter what. Decision: two-layer architecture. Infra layer = **agenix** (encrypted-in-git, decrypt at activation; closes Q3). Things layer = **swappable backend chosen at bnox config time** — `file` (default, plaintext files at `/var/lib/bnox/secrets/<thing>/<slot>/`, watched by systemd-path, restart on change, no rebuild) OR `nats-kv` (designed-for, not built day-1; secrets-service fetches from NATS KV using host key). Slot contract identical across backends (Q9.5). Default = `file` because day-1 single-host + Q14 guardrail. Both backends ship as user-facing config options — adopting users pick at config time. bnox module structure: `secrets/{infra.nix, backends/file.nix, backends/nats-kv.nix}`. Q3 + Q11 resolved. Q12 (host key home) tightly coupled, still open.

2026-07-27 — **D-008 ACCEPTED — Host encryption key = SSH host key** (`/etc/ssh/ssh_host_ed25519_key`). No separate bnox-managed key. agenix reads via `age.sshKeyPaths` (default). Future `nats-kv` backend derives from same key. Provisioned via nixos-anywhere. **Recovery via second age recipient on every agenix secret**, held off-host (operator's workstation) — not via `/etc/ssh/` backup. TPM path documented as future hardware-host enhancement. Q12 resolved. 5 decisions accepted (D-001, D-002, D-006, D-007, D-008).

2026-07-27 — **Per-thing user isolation locked (Q9.6, refinement to D-006).** Every enabled thing gets a dedicated system user, auto-created by bnox. Applied uniformly to all things — not just third-party or daemon-shaped. Default user = thing name. systemd hardening by default (`ProtectSystem=strict`, `ReadWritePaths` scoped to thing's paths, etc.). Secrets file ownership set automatically. Cost: effectively zero (automated by thing abstraction; mild debugging friction accepted as feature). Justification for uniform application: defense in depth + consistency + L1 NATS upgrade path is free. Will roll into D-006.1 alongside multi-component refinement when design settles more.

2026-07-27 — **Per-thing security model locked (Q9.7, refinement to D-006).** User isolation alone is necessary but not sufficient — does not isolate network or RAM/CPU/disk. bnox applies a **standard hardening bundle** per thing (filesystem lockdown, capability stripping, syscall filtering, process visibility hiding, cgroup resource caps, network egress allow-list). Directives catalogued in `working/open-questions.md` Q9.7. Honest threat model documented: kernel exploits remain (out of scope); compromised thing is contained to its own state + outbound network (within allow-list) + resource budget. Per-thing overrides available for legitimate special needs (e.g. daemon needing outbound HTTPS), declared in host config (visible, not silent). Will roll into D-006.1 with Q9.6.

2026-07-27 — **D-009 ACCEPTED — Hermes deviation (first use of Q14 escape hatch).** Hermes is hosted as a `daemon`-shape thing with new `host-install` runtime — runs on host (not container) under dedicated `hermes` user, managed by systemd. Deviation scope: ONLY D-002's Nix-only-images rule waived for Hermes specifically; all other decisions (D-006 architecture, D-007 secrets, Q9.6 user isolation, Q9.7 hardening) apply unchanged. Hermes sandbox backends restricted to `local` only (no Docker/SSH). **Supporting refinements locked:** Q9.8 (new `daemon` shape — long-running stateful process, no inbound HTTP/NATS), Q9.9 (new `host-install` runtime option — orthogonal to shape, requires Q14 deviation per thing). **Q14 RESOLVED** → NFR-6 (deployment simplicity ceiling with deviation clause). 6 decisions accepted total.
